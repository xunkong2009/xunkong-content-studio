## 分享版个人配置

用户当轮提供的材料和要求优先。需要语料库、主播照片或本地字体时，可读取当前项目的 `.xunkong-studio/config.json`（如存在）；相对文件路径以当前项目为基准。配置示例见插件根目录 `config.example.json`，不要改写安装目录。

未配置语料库时使用随包风格规则继续写作；未配置真人参考照片时可先交付提示词或无人像方案。需要复现某个真人且缺少参考时，向当前用户索取参考，不使用发布者的身份。配置文件中不存储 API Key、密码或账号 Cookie。

# 商业深度调研

## 概述

把一个题目或论点，做成足以支撑锋利文章的证据底座。优先官方材料、原始文件、采访、财报、政策文本、会议纪要与经过交叉验证的媒体报道，而不是二手摘要。

## 必需上下文

- 阅读 `../deep-biz-wechat-writer/references/style-layer.md`
- 阅读 `../deep-biz-wechat-writer/references/source-policy.md`
- 阅读 `../deep-biz-wechat-writer/references/workflow-rubrics.md` 中的 `ResearchBrief` 部分
- 只要题目涉及当前信息，就必须在线核验

## 工作流

1. 用一句话重述研究问题
2. 把问题拆成 3-6 个可独立核验的子论点
3. 从高质量中外来源搜集证据，优先原始材料与权威报道
4. 关键论点尽可能做到至少两路独立来源交叉验证
5. 明确区分确定事实、市场解读与未决不确定性。按题目需要补充少量作品、人物处境或生活场景候选，选材时阅读 `../deep-biz-wechat-writer/references/author-voice.md`。在 `ResearchBrief` 的可直接进入文章的洞察中简记来源、具体连接和核验状态，与事实证据区分；无合适材料可不加
6. 最终返回一个 `ResearchBrief`

## 输出规则

- 按 `核心论点 -> 证据 -> 来源 -> 可信度 -> 推断说明` 组织
- 当前议题要标明具体来源名称和日期
- 合理但未被证实的判断必须标成推断，不能伪装成事实
- 如果两个高可信来源相互冲突，要把冲突写出来，而不是强行抹平
- 只保留真正能增强文章的证据，不要把原始搜索结果整包倾倒出来

## 信源优先级

- 优先级 1：官方文件、财报电话会、政策文本、公司公告、原始采访、原始数据集
- 优先级 2：高可信媒体报道，如 Bloomberg、The Economist、Financial Times、New York Times、Businessweek、WSJ、Reuters、财新、36Kr、虎嗅
- 优先级 3：优质行业媒体、专家 newsletter、Substack、Medium 与 Reddit 讨论串，但只能当作信号或叙事纹理，不能单独当证据

## 失败模式

- 把链接数量误当研究深度
- 把观点聚合误当证据
- 为了让论点显得顺，把不确定性藏起来
