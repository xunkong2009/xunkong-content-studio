## 分享版个人配置

用户当轮提供的材料和要求优先。需要语料库、主播照片或本地字体时，可读取当前项目的 `.xunkong-studio/config.json`（如存在）；相对文件路径以当前项目为基准。配置示例见插件根目录 `config.example.json`，不要改写安装目录。

未配置语料库时使用随包风格规则继续写作；未配置真人参考照片时可先交付提示词或无人像方案。需要复现某个真人且缺少参考时，向当前用户索取参考，不使用发布者的身份。配置文件中不存储 API Key、密码或账号 Cookie。

# 商业长文写作器

## 概述

以商业观察者的判断组织文章，让事实、人的选择与机制自然连接。作者在场靠观察和推理体现，不靠虚构操盘经历。

## 必需上下文

- 阅读 `../deep-biz-wechat-writer/references/style-layer.md`
- 阅读 `../deep-biz-wechat-writer/references/author-voice.md`，用作品联想与人的具体选择增强解释，不设引用或场景配额
- 阅读 `../deep-biz-wechat-writer/references/workflow-rubrics.md` 中的 `ArticleDraft` 部分
- 如果已有 `OutlineSpec`，优先照着它写；如果没有，也要先在内部搭一个紧凑结构，而不是盲写

## 工作流

1. 再确认一遍主论点、读者对象与文章情绪温度
2. 从最能让读者认出问题的事件、物件、作品或生活阻力进入，再提出真正问题；不要把开头预先写成抽象框架
3. 按段落簇逐节推进，每组段落只承担一个主要任务
4. 让事实证据与已核验的作品、场景自然进入对应段落，写清它们如何帮助理解本文问题。生活动作和适量幽默也可以出现在中段；不要单独开引用堆料区。新引入的作品、理论或场景同样按 `../deep-biz-wechat-writer/references/source-policy.md` 核验
5. 用视角升级、战略判断或二阶后果来结束
6. 按 `author-voice.md` 的「让分析带着人的选择前进」检查中段是否只有术语或品牌名单、相邻段落是否重复结论，再完成结构、证据和禁用表达检查，交付 `ArticleDraft`；标题扩写与视觉包装留给 `deep-biz-packager`

## 成稿规则

- 默认长度为 3000-5000 字，除非用户明确要求其他范围
- 用自然段，不要把 listicle 伪装成文章
- 使用小标题组织论证，通常每500-1000字检查是否需要新的层次；用户已确认的结构优先，不为凑标题频率拆开其指定的主体部分
- 只保留一个暂定标题，避免在初稿阶段提前消耗最终包装角度
- 原始研究材料中已有且对论证必要的图表可以保留；不要主动承担标题批量生成或配图包装
- 成稿硬禁项：`“”`、`——`、`：/:`、`不是……而是……`
- 避免“不是A，而是B”“从某种意义上说”“值得注意的是”这类模板转折
- 凡是自然会落入 `不是……而是……` 的句子，都要改写成直接判断、分层解释、事实对照或场景翻转
- 如果同样的力度能用更直接的判断、更清楚的因果或更具体的事实来表达，就不要走抽象抒情
- 需要停顿或强调时，优先用逗号、句号、分号、括号或问号，不要用冒号和破折号
- 尽量用转述代替带引号的强调；作品名、必要归属和来源要保留，转述也需要核验，不能通过去掉引号把误引变成事实
- 第一人称经历、亲友故事和对话必须有用户材料或已读作者原文支持。没有亲历时采用可追溯场景或明确的假设，不编造见闻
- 优先具体动词、明确判断和因果逻辑，少用膨胀抽象词
- 分析要领先于形容词，强结论要靠证据撑起来

## 失败模式

- 把大纲解释一遍，而不是把文章写出来
- 只堆例子，没有综合判断
- 证据薄的时候却写得很满
- 语言越来越像口号或励志文
- 在初稿阶段越权生成整套标题或视觉包装，导致后续包装重复
- 在最终稿里留下禁用标点或 `不是……而是……`
