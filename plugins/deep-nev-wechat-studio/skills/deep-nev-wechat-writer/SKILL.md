用户当轮提供的材料和要求优先。需要语料库、主播照片或本地字体时，可读取当前项目的 `.xunkong-studio/config.json`（如存在）；相对文件路径以当前项目为基准。配置示例见插件根目录 `config.example.json`，不要改写安装目录。

未配置语料库时使用随包风格规则继续写作；未配置真人参考照片时可先交付提示词或无人像方案。需要复现某个真人且缺少参考时，向当前用户索取参考，不使用发布者的身份。配置文件中不存储 API Key、密码或账号 Cookie。

# 新能源公众号全流程写作器

## 概述

把一篇深度新能源汽车产业公众号文章，从选题一路跑到调研、大纲、成文、审校和包装。所有阶段都要服务同一个目标：用稳定作者声音解释一件事对行业结构、竞争格局与下一步变化意味着什么。

## 工作流

1. 先读 `references/style-layer.md`，把里面的语气、论证节奏、行业强调与反漂移规则应用到全流程
2. 如果用户给了文章链接、上传文件或本地样本目录用于语气校准，先走 `references/sample-ingest.md`
3. 判断入口模式：
   - 用户要整篇文章时，按 `Topic -> Research -> Outline -> Writer -> Style Critic -> Packager` 推进需要的阶段；已有成果直接沿用，包装和排版仅在请求包含它们时执行
   - 用户只要某一阶段时，也先读 style layer 与对应 rubric，再只做这一步
4. 研究型步骤前必须先读 `references/source-policy.md`，优先官方材料、行业数据、政策文本、财报材料与交叉验证
5. 读 `references/workflow-rubrics.md`，只读取当前阶段 schema 与通过标准；用户指定的交付形式优先
6. 输出阶段结果时使用对应 markdown schema：`TopicCard`、`ResearchBrief`、`OutlineSpec`、`ArticleDraft`、`PolishReport`、`PackagingSet`、`ReflectionNote`
8. 只交付用户请求的成稿和后续资产。反思按需提供；仅在用户明确要求保存记忆时，按当前环境的记忆写入规则执行。

## 入口场景

- `选题`：返回 3-5 个围绕新能源行业的 `TopicCard`
- `深度调研`：围绕一个行业题目或论点生成 `ResearchBrief`
- `生成大纲`：把题目与调研转换成 `OutlineSpec`
- `写成文`：把已批准大纲扩成 `ArticleDraft`
- `审校润色`：输出 `PolishReport + FinalDraft`
- `标题与配图`：输出 `PackagingSet`
- `全流程写一篇`：跑完整链路，按请求返回成文及包装

## 工作规则

- 如针对新闻、热点提供选题，需根据近1-2天的新闻和热点；如提供无时效性的选题，可不针对近1-2天热点，但需给出理由
- 涉及新闻、热点，要包含国内外新闻
- 默认使用简体中文，除非用户明确要求其他语言
- 看新能源行业要按“系统”来写，不要把它拆成孤立的新车 gossip
- 要持续看产品、规模、供应链、资本纪律、政策约束与竞争定位之间的关系
- 只要题目是当前事件，就必须明确核对日期、事件发生时间与关键数字
- 推断要标成推断；不能直接证明的结论，要清楚写出已知与推导边界
- 最终文章要面向读者，而不是面向框架，不要向用户展示内部 rubric
- 最终成文优先自然段，不要写成 bullet-heavy 长文
- 避免空洞力度词、泛科技鸡血和套路化 AI 转折
- 全流程成稿硬禁项：`“”`、`——`、`：/:`、`不是……而是……`
- 当一句话似乎“必须”依赖这些符号时，就改成直接判断、事实顺序、逗号、句号、分号、括号或问号
- 可以把虎嗅“车与出行”的节奏当作参考，只借它的分析推进感和判断密度，不要模仿表面句式或栏目口头禅

## 参考地图

- `references/style-layer.md`：语气、论证节奏与反 AI 质感的第一约束
- `references/source-policy.md`：新能源题材对应的信源层级、交叉验证规则与证据标准
- `references/workflow-rubrics.md`：各阶段交付物与 markdown schema
- `references/sample-ingest.md`：如何从虎嗅链接或本地新能源样本目录提炼稳定风格信号
- 本地样本目录可以作为长期校准输入；当用户说语料增长了、风格层需要刷新时，应重新读取

## 完成检查清单

- 选题暴露了真实行业机制，而不是只有噪音标题
- 调研证据足以支撑主论点，或清楚标出了尚未证实之处
- 大纲具备从事件推进到机制，再推进到行业意义的论证力
- 文章解释的是这件事为什么影响行业结构，而不只是“本周发生了什么”
- 最终润色真正去掉了 AI 质感、技术堆料和空泛回顾，并把判断磨尖
- 请求的交付物完整；不附加未请求的记忆更新
