# 工程与审片质量门

## 清单驱动

`project-manifest.json` 是唯一渲染入口；包含原文/范围词、视频规格、styleTokens、片段ID/文件名、时长、稳定帧、转场帧与每段audio模式/音效事件。新工程 schemaVersion=2，每段有 motionDesign；未指定版本或版本1的旧工程继续兼容。

`preflight` 验证主题范围与残留词、登记Composition及清单结构；存在 visualAssets 时另查本地图片、生成提示词、参考路径与片段 assetIds 引用，纯代码和未升级旧清单继续兼容。新版还检查动作顺序、帧范围、原文锚点、覆盖方式与录音证据字段。程序无法证明口播事实、对象含义、代码与计划一致或实际声画同步。

## 预览顺序

1. `npm run preflight`、`npm run lint`。
2. `npm run preview:motion`：每段生成低成本连续 MP4 和 `preview/motion/index.html`。
3. `npm run preview:audit`：生成稳定/转场缩略图，以及每段一个全尺寸细节帧；可用 detailFrames 增加关键细节。
4. 实际观看正常速度连续视频，随后逐张检查关键帧；修正后重生成受影响预览。

每段至少4个稳定帧、1个转场帧。应覆盖开头、关键变化后、结果和结尾；动作起终点及中间容易交叠的位置额外采样。连续预览验证节奏，全尺寸帧验证文字与细节，二者互补。无法播放时明确限制；密集连续抽帧只能验证运动路径，不能声称已完成正常速度听审。

## 视觉检查

- 问题与答案：最终画面回答本段标题/观看问题？只展示差距的图没有暗示未经支持的原因？
- 含义：主体真的发生了设计中的变化？迁移有可识别的接收对象或终点？移动终点/合并结果准确？列表没有强行伪装因果？
- 节奏：首帧没有后段关键数字/答案提前出现；信息按口播顺序出现，有读完文字和理解图表的停留？没有一直抖动、计数或缩放？
- 连续性：主体身份稳定，聚焦后仍能定位，转场无无关信息残留或文字重影？
- 转场危险点：数字合并、路径交叉、遮罩切换需看首次接触与交叠中点；先清理旧标签/运算符，再让新结果接管。必要时对风险区间密集抽帧，方法见 `shot-craft.md`。
- 目标画幅阅读：按清单核对横竖屏及尺寸；横屏约640×360、竖屏约360×640下主体足够醒目，必要数字/标签可读；没有把生产状态、估算节奏等交付说明贴进观众画面。
- 可用性：首尾可直接接剪辑，关键结果不以空白结束；平台/字幕区不冲突？
- 文字/图形：无孤字、裁切、遮挡或越界；单位、刻度、数据和原文正确，示意/假设标注可读？
- 图片主体：人物/产品身份与变体一致，五官、手部、包装准确；透明边缘干净、可见大小足够，落地/持物/遮挡合理；姿态切换不重影、不滑脚、不任意换衣。检查过渡中点和全尺寸细节，不能以文件存在代替视觉检查。
- 音效：正常速度试听触发时刻、密度、音量、尾音与剪辑衔接；有口播时混听，未试听不能宣称听审通过。
- 声画：只有存在授权录音并实际检查时才声明已同步；估算插片在交付中说明。

## 渲染与交付

视觉通过后运行 render:all → verify → package。ffprobe 按 renderProfile 检查 H.264 / ProRes / VP9、透明像素格式、尺寸、帧率、时长、音轨与每段设计模式一致（silent无音轨、sfx 有 AAC，WebM 使用 Opus 音轨），输出媒体检查报告。压缩包包含manifest、工程、预览、报告与成片；图片项目同时包含实际引用的public素材、asset-prompts生成提示词和存在的visual-asset-plan.md，排除node_modules。

`deliver` 先生成连续预览和关键帧，再暂停审片；`--visual-approved` 代表实际视觉审查完成，不是绕过检查的快捷开关。最终报告分别写程序检查、视觉检查及尚未验证的事项，不能把渲染成功等同效果提升已经被观众确认。

## 模板与浮层
逐类按 nine-templates.md 检查；浮层须在实际主播底片检查入场、停留、退出及头部移动，不把透明画布截图当成叠加验收。允许肩手被覆盖。模板可横竖屏重排；九类样例通过不代表真实项目同步通过。透明导出验证 codec、alpha像素格式并抽查实际 alpha；预览与最终透明格式分别注明，MP4预览不证明透明已通过。音效交接提供同源 WAV stem 和实际触发点，素材原声不隐式保留。

## 主播文字与声音返工的补充核对

在实际主播底片上检查无底框文字对比、金黄重点和白字黑边；从完整显示窗口的入场、中段、出场核对普通字幕已隐藏或错位，不残留几帧重叠。原有动作完整性需实际成立，主体上行/跌落不能只是整图平移。

从最终导出核对所有计划音效事件，保留人声验证和峰值记录，并提供含口播上下文的试听；音效事件存在性等程序结果不能冒充听审。正常速度听感未检查时如实标待试听。
