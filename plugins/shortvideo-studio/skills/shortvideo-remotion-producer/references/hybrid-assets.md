# 主体图片与代码动效的混合制作

先规划动作，再决定需要什么素材。目标是让具体主体好认、自然且能参与解释；不是给每段增加图片，也不是生成一张整页后只做缩放。

## 选择表现方式

| 内容 | 优先方式 | 关键判断 |
|---|---|---|
| 人物、动物、服装、食物、有材质的物品 | 合适的现有图片；缺少时按需图片生成 | 五官、比例、手部、质感或辨识度是理解的重要部分时，避免临时拼凑粗糙形状 |
| 特定品牌产品、包装、Logo、设备界面 | 用户已有或项目中准确的原图 | 不能把生成的近似包装、商标和界面当成真实产品证据；没有准确图时可用明确的品类示意，必要文字由代码叠加 |
| 数字、中文标签、图表、公式、箭头、关系线 | 代码 | 保持精确、可编辑；无依据的数据不靠图片补造 |
| 简单几何主体、抽象机制 | 代码或现有图形 | 运动关系比外观细节重要时，直接绘制即可 |
| 背景与环境 | 现有图形或按需生成 | 与主体分层，给文字和动作预留空间；不把可变关系烘焙进背景 |

用户明确限制素材方式时优先遵守。只有方案或提示词请求时，交付到相应阶段。已确认视频制作时可连续完成必要素材准备与自检，不为每张图片新增用户确认门。

## 从动作倒推素材

涉及多张主体图时，使用简短素材表或直接在选段计划中记录：主体、出现节拍、来源方式、必要状态/视角、透明/分层要求、尺寸与落位锚点。只做动作实际需要的状态，不机械要求每个人物都生成三套姿势。

- 人物需要从休息切换到电脑工作：先确定同一人的服装、发型和脸部；生成母图，再以母图/已检查坐姿为参照生成工作状态。姿态图保持镜头、大小、头部和双脚位置可对齐。
- 产品需要从货架移到用户手中：准备可独立移动的产品 cutout，并确定手与产品的前后遮挡；不要只生成已经粘在整页背景里的产品。
- 只有品牌体系与价格对比：可用准确品牌名称、现有产品图或品类示意配代码关系图，不必生成“看起来像官方”的商品图。
- 人物需要连续关节动作：评估分层素材或专用动画能力；若当前仅能提供离散姿态，采用明确切换/遮挡转场，不把静态图拉伸成不自然的肢体动画，也不把静态姿态切换宣称为连续表演。

## 图片生成与一致性

需要生成时，读取当前可用的 `imagegen` Skill，优先内置图片生成工具，不自行编写图像 API 调用。图片工具不可用或失败时，遵守其回退授权要求；可说明缺项并先做不依赖该资产的工作，不声称素材已生成。

提示词写清：资产用途、参考图的角色（风格/人物身份/产品外观）、主体、视角与姿态、完整取景、需保持的特征、透明背景或场景、与后续动作有关的留白和分层。必须保留的服装、名称和方向来自用户与脚本，不擅自照搬参考图中的无关信息。

同一人物或同一产品的变体按依赖顺序制作：母图 → 实际查看 → 以母图为参考衍生必要状态 → 对比查看。相互独立的主体可分别生成。要求透明背景时向工具明确请求真实 alpha；看得到棋盘格不等于图像具有透明通道。默认不把中文标签、价格、箭头和关系线一起生成进主体图。

生成结果必须实际查看：主体、完整轮廓、手与持物、服装/包装、边缘与背景、需要保留的特征。不合格时做针对性修正；同一缺陷连续修正两次仍不满足时，说明具体限制并转用可成立的方案，不无上限重抽。不得跳过检查直接批量套用母图。

## 工程登记

最终被引用的图片复制到工程 `public/visuals/`，通过 `staticFile()` 加载；不得只引用工具默认输出目录、系统临时路径或易失远程地址。原始参考按需要复制到 `public/references/`。生成提示词保存为工程内 `asset-prompts/` 的 Markdown 文件，提示词与素材分别保留，便于重做和打包。

`project-manifest.json` 的可选 `visualAssets` 与片段的 `assetIds` 不改变 schemaVersion；新图像项目填写，纯代码可留空，旧工程不强制迁移。例：

```json
{
  "visualAssets": [
    {
      "id": "mom-working",
      "type": "character",
      "src": "visuals/mom-working.png",
      "sourceType": "generated",
      "source": "内置 image_gen，根据用户人物参考与本项目坐姿母图生成",
      "promptPath": "asset-prompts/mom-working.md",
      "referencePaths": ["public/references/mom.png", "public/visuals/mom-seated.png"],
      "identityGroup": "mom",
      "variant": "seated-working"
    }
  ],
  "clips": [{"assetIds": ["mom-working"]}]
}
```

此处是字段片段，合并进现有完整清单；`src` 相对 `public/`，`promptPath`、`referencePaths` 相对工程根目录。`type` 支持 `character`、`product`、`prop`、`background`、`other`；`sourceType` 支持 `user`、`existing`、`official`、`generated`。`identityGroup` 与 `variant` 仅在需要管理同主体变体时使用。生成资产必须有提示词文件，已有资产只需真实来源。复用同一素材时使用同一 id。

preflight 检查登记结构、id 引用和本地文件/提示词/参考是否存在；不自动判断形象一致、透明边缘、来源真实性或美感。项目包包含 public、asset-prompts 和存在的 visual-asset-plan.md，不依赖外部生成目录。

## 合成与审片

按主体可见边界布置画面，避免透明留白导致人物过小或脚底悬空；用 contain 保持比例，按需要裁切并保留正确锚点。图解、主体、前景持物和字幕分别管理层级，关系线不要穿过脸、身体或必读文字。

先检查动作前、变化中、结果三种构图，再检查正常速度视频。姿态切换特别看头部是否跳位、衣服是否换款、双脚是否滑动、电脑是否穿过手；两张脸不能靠长交叉淡入叠在一起。可用明确剪切、匹配切换或局部遮挡处理离散姿态。

全尺寸检查五官、商品细节与 alpha 边缘；缩至目标播放尺寸检查主体辨识和文字。不同姿态只需要一致的身份与合理连续性，不强制生成不必要的逐帧动作。
