## 分享版个人配置

用户当轮提供的材料和要求优先。需要语料库、主播照片或本地字体时，可读取当前项目的 `.xunkong-studio/config.json`（如存在）；相对文件路径以当前项目为基准。配置示例见插件根目录 `config.example.json`，不要改写安装目录。

未配置语料库时使用随包风格规则继续写作；未配置真人参考照片时可先交付提示词或无人像方案。需要复现某个真人且缺少参考时，向当前用户索取参考，不使用发布者的身份。配置文件中不存储 API Key、密码或账号 Cookie。

# Remotion 短视频动效制作

先确定观众要看懂什么、主体怎样变化，再选择素材形式。默认采用“按需准备主体图片＋代码编排动效”的混合流程：人物、产品、服装和场景等具象主体优先复用合适素材，代码难以表现时调用图片生成；文字、数字、图表、箭头和关系线由代码准确呈现。纯图表或简单抽象机制可全程用代码。默认制作竖屏 9:16 的独立插片或主播浮层；用户明确要求横屏才制作横屏，并重新设计布局。主播固定机位录制，效果由后期完成，不要求主播为动效换角度、移位、让出空间或配合手势。

用户已授权视频制作时，必要的主体图片生成属于制作步骤，无需另开一轮请求；仅要方案、提示词、参考研究或 Skill 优化时不启动生成和成片制作。配音、背景音乐和网络视频素材不自行生成或下载；短动作音效按 `references/sound-design.md` 执行。

## 按阶段读取

- 选段前：`references/motion-selection.md`；选择九类基础模板、填写参数时读 `references/nine-templates.md`。
- 设计每段动作、分析参考视频前：`references/motion-language.md`。
- 提取风格或实现画面前：`references/layout-and-style.md`；主播上的文字和字幕共存时同时读取 `../talking-head-video-editor/references/final-composite.md`。
- 需要人物、产品等图片主体，或代码绘制效果不足时：`references/hybrid-assets.md`；需要生成/编辑图片时同时读取当前可用的 `imagegen` Skill，使用其内置工具流程。
- 优化视觉效果，或设计迁移、合并、聚焦镜头时：`references/shot-craft.md`。
- 设计声音或制作带音效片段时：`references/sound-design.md`。
- 建工程、审片、交付前：`references/quality-gate.md`。
- 实现代码时同时使用当前可用的 Remotion 创建、Markup、渲染规范。

## 默认值与边界

- 简体中文，默认竖屏 9:16、1080×1920、30fps；明确要求横屏时使用 1920×1080。用户指定规格优先。全屏插片默认 H.264 MP4；透明浮层输出 ProRes 4444 MOV 或 VP9 WebM，剪辑兼容性需实际验证。
- 默认主题 `navy-gold`：深蓝 #070B11、金 #F7CB56；保留 `cream-red`：米白 #F6F1E8、黑 #151515、红 #C62828。主题与模板、画幅分别选择。
- 浮层可覆盖主播部分肩膀和手，脸部含运动余量为保护区，字幕另设安全区。根据已有视频确定区域；主播位置不动，优先调整浮层的位置、尺寸、分组与出现顺序，不要求重录让位。
- 根据内容、语气与关键动作主动选择少量短音效，无需用户逐次提出或另行确认；迁移、落位、数据揭示或内容反差可配声音，阅读与停留保持安静。用户要求无声时全部无声。
- 按内容选择模板和数量，不要求用齐九类。关键词可只覆盖短语，解释插片按实际口播分配时长；不为凑 4–6 段或 6–12 秒压缩论证或拉长强调。
- 保留用户原文、数据、品牌名和判断。脚本未定稿或有待核验事实时交回相应写作/调研阶段。
- 区分覆盖整段原文的 `full-excerpt` 和只服务局部短语的 `illustrative-insert`，记录插入锚点。没有录音时只能称为估算节奏。
- 区分参考的用途：风格图用于视觉语言，人物图可用于保持形象，产品图用于准确识别；用户明确要直接使用的资产可入片。参考视频截图不作为交付素材，不推断其制作软件或未观察到的技术。
- 用户指定只用代码、只用现有素材、仅输出提示词或其他素材边界时直接沿用；不为混合流程强制生成图片。

## 工作流

用户只要求参考研究、效果评价或优化 Skill 时，抽样查看参考与已有作品并记录证据；按请求交付研究或评价，只有要求优化 Skill 时才修改规则并验证。不套用选段确认或启动成片制作。只要设计方案时交付方案；“直接做”取消重复确认，不扩大用户指定阶段。参考不可播放时说明实际观察范围，不把封面、标题或文稿当成动态观看证据。

### 1. 锁定范围

核对脚本主题、主体、选中原文、画幅与分辨率、参考、目录、Composition ID、文件名。防止上一项目品牌、数字或构图残留。已有 `VisualBeatPlan` 只处理分配给 Remotion 的节拍，保留 `beat_id`，不重拆全文。

### 2. 选段并设计变化

输出 `MotionSelectionPlan`：原文、观看问题、视觉对象、初始→变化→结果、口播触发短语、注意力焦点、画幅与构图、时长依据、覆盖方式、页面文字、声音用途/触发点（或保持无声的理由）和确认状态。涉及具象主体时，同时说明哪些复用素材、哪些按需生成、哪些用代码，以及动作需要的姿态/视角/分层；简单纯代码段无需额外素材表。

默认确认选段再实现；用户已说“直接做”“继续”“不用确认”或给出同义授权时连续推进，不重复设置确认门。

在全流程项目中，脚本阶段先规划模板、素材和风格样例；以确定后的粗剪及其 SHA256 为正式计时基准，再制作最终动效。已有明确时间轴时直接沿用。无录音可做估算插片，但标记待对齐，不为适应动画变速或改写人声。

### 3. 建立共同视觉语言

提取 `styleTokens`，确定主体身份的颜色/形状、字号、素材用法和安全区。每段按观看问题选择构图；整批保持品牌语言，避免所有段落套同一标题—卡片—结论页面。

参考视频分析至少记录：观察时间段、对象如何变化、信息何时出现、视线如何移动、哪里停下来，以及如何转译到当前内容。取其讲解方法，适配本次横屏或竖屏画幅和用户风格。需要打磨的片段按 `shot-craft.md` 明确首帧已知/后续揭示、主体起终点、焦点交接和可见答案；在既有计划中记录，不额外增加确认流程或强制清单字段。

### 4. 初始化和填写清单

独立任务默认 `<workspace>/output/remotion/<topic>-motion-clips/`；工作台任务使用项目 `motion/`。

```bash
node scripts/create-project.mjs --output <project-dir> --topic-key <slug> --title <project-title>
```

初始化默认竖屏、深蓝金；明确要求横屏时加 `--orientation landscape`，米白黑红主题加 `--theme cream-red`。生成九类可运行样例时加 `--gallery`；该样例仅供模板验证，正式项目须替换原文和资产。其他指定画幅在初始化后修改清单 `video.width` / `video.height`，再按目标画布重新排版。不能只改导出尺寸或裁切、拉伸另一画幅。

新工程使用 `schemaVersion: 2`；图片资产登记在可选 `visualAssets`，片段通过 `assetIds` 引用，规范见 `references/hybrid-assets.md`。纯代码工程可留空，旧工程无这些字段仍兼容。完整填写 `project-manifest.json` 中每段的 `motionDesign`，填写每段 `audio` 的模式和音效事件，再写 Clip 并登记 `src/clip-registry.tsx`。旧工程允许保留原清单结构；针对本次修改的片段补充设计说明。所有预览、渲染和校验只读取清单。

### 5. 准备并检查主体素材

工程初始化后，按已确认动作所需的最小素材集复用或生成主体。具体执行 `references/hybrid-assets.md`：先明确透明背景、朝向、姿态、锚点和分层，再调用图片生成；同一人物/产品以母图为参照衍生必要状态。图片生成后实际查看，复制到工程 `public/visuals/`，保留来源与生成提示词；检查通过再进入正式动效。生成失败时遵循工具边界，说明缺项，不静默改用未经授权的付费 API 或劣质占位图。

### 6. 实现与连续调度

- 时间由 `useCurrentFrame()` 驱动，秒数用 `useVideoConfig().fps` 换算；禁止 CSS animation/transition。优先 scale、translate、rotate。
- 先建立主体，再用移动、拆分、合并、累积、比较或焦点切换解释内容；单纯列表可逐项揭示，但必须给出阅读顺序和停留。
- 图片主体负责外观，代码负责迁移、聚焦、比较、遮挡和信息揭示。需要转身、抬手、拿电脑等结构变化时使用匹配姿态或分层素材，不拉伸整图模拟关节；姿态切换核对头部、脚底与持物锚点，避免重影。
- 同一推演保留对象身份和空间参照；独立场景清除无关旧信息。不要为转场强制把所有共享对象退出重建。
- 一次突出一个主要变化，其他对象降低显著性；动作后留阅读时间。数字跳动、弹跳、镜头缩放都须服务含义。
- 根据内容选择音色，声音跟随动作或揭示的准确时刻，与动作一起设计；只突出少数关键点，音效不能替代视觉解释，不默认添加背景音乐或人声梗。
- 首尾保留可用稳定画面，便于接主播或素材；标题和结论按需要出现，避免提前泄露反转。

### 7. 连续预览与审片

```text
npm run preflight
npm run lint
npm run preview:motion
npm run preview:audit
```

以正常速度实际检查 `preview/motion/index.html` 的视频，再检查 `preview/audit/index.html` 稳定帧、动作边界与全尺寸细节。检查含义、触发节奏、视线、停留、插入接口、文字与遮挡；含图片主体时另查人物/产品一致性、透明边缘、落地点、持物关系、姿态切换和小尺寸识别；修正后重生成受影响预览。截图检查不能替代连续播放；带音效片段必须试听音画触发、音量、尾音和接剪辑效果；有授权口播音轨才检查是否干扰口播及真人声画同步。模板在渲染画面后按清单混入音效，Studio只预览画面，完整声音以连续 MP4 预览为准。

通过视觉检查后：

```text
npm run render:all
npm run verify
npm run package
```

`npm run deliver` 生成连续预览和审片页后暂停。实际视觉审查通过才使用 `npm run deliver -- --visual-approved`。不能仅凭程序成功声明效果通过。

## 交付

说明实际完成的段落、规格、声音模式、素材来源、观看/试听情况及限制，提供独立 MP4、连续预览、关键帧审片、ZIP 和可编辑工程；使用图片时把实际引用的主体素材、来源与生成提示词随工程交付。用户只要求优化 Skill 时交付更新说明与验证结果，不启动未请求的脚本制作。

模板使用 `clip.templateId`、`presentation`（`fullscreen` / `overlay`）、`templateProps` 与可选 `renderProfile`，详见 `references/nine-templates.md`。沿用 schemaVersion 2 和旧定制 Clip；新增字段可选。所有时刻最终以 motionDesign.beats 为依据，templateProps 的揭示时间与审片帧同步更新。
